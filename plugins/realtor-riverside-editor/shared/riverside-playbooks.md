# Riverside playbooks (the tested recipes)

Claude edits directly; Riverside renders; the agent approves. These use the Riverside connector's **real tools** — names as the connector exposes them (the `editing_` / `platform_` / `exports_` / `social_` / `media_` prefixes are dropped here for readability). The job-by-job index is `${CLAUDE_PLUGIN_ROOT}/shared/tool-map.md`.

## The tools you actually call

**Find & read (free, change nothing)**
- `platform_list_recordings` → the agent's videos. **A recording whose `status` is `uploading` or still processing is not editable yet** — say *"still uploading, give it a few minutes"* and wait; don't create an edit against it. Uploads and single-take recordings use `id` as the `sessionId`.
- `platform_get_recording(recordingId)` → the recording plus its `project.id` and `studioId` (you need both). `platform_get_project(projectId)` → recordings + existing edits in one call. `platform_list_edits(projectId)` → edits already made (filter `deleted: true`).
- `platform_get_transcript(sessionId)` → prose with `Speaker (m:s.mmm)` per sentence — for the pre-flight read. `read_aligned_transcript(editId, includeParalinguistics:true)` → compact rows (`spanId`, `playableStartMs/EndMs`, `fillerCount`, `pauseCount`, `startsMidSentence/endsMidSentence`) plus `paralinguistics[]` (emotion and affect events with a score, on the PLAYABLE axis) — for cut planning and the zoom plan; `detail:"words", startMs, endMs` in a window for exact boundaries (`maxWords` defaults to 200, max 1,000; `maxBytes` 65,536, max 262,144). Both return the current `revision`.
- `read_timeline_in_range(editId, startTime?, endTime?)` → tracks (`uniqueId` = `trackId`), clips (`uniqueId` = `clipId`), scenes (with `slotSettings`), `syncedCuts[]` (with `source`), `chapters[]`, keyframes, the recording clip's `comments[]` (Riverside's own AI notes, `source:"ai"`, source-time ranges), and `settings.canvas`. Read a narrow window; don't dump the whole timeline.
- `get_revision(editId)` → cheap "did anything change?" check. `compare_revisions(editId, fromRevision, toRevision)` → the diff: cuts/mutes/scenes created/modified/deleted with the feature that made each (`removeFillerWords` / `removePauses` / `smartMute` / null = ours), toggles, volume changes, duration before/after. **This is how you verify a pass.**
- `get_captions_presets(studioId)` / `get_brand(studioId)` / `list_layouts(aspectRatio, participantCount)` / `get_stock_media(query, mediaType)` / `get_stock_music(collection, section)` / `media_list_media(productionId, search)` / `get_asset_metadata(assetId)`.

**Make the working copy**
- `create_edit_from_recording(sessionId, projectId, title)` → `editId`. The recording is never modified. **Not gated on Grow (live-tested).** If it ever returns `FAILED_PRECONDITION`, fall back: *"Open the recording in Riverside and hit Edit once — I'll take it from there,"* then `platform_list_edits(projectId)` and use the newest one. Don't retry the gated call.
- `clone_edit(sourceEditId, title)` → a full copy. Two uses: (1) the **snapshot** before the first destructive pass when the recording exists nowhere else (recorded straight in Riverside and never downloaded) — continue on the ORIGINAL, the clone is the safety copy, say *"I saved a copy of your original first"*; (2) the **cut-only master** (below) that reels and the trailer are cloned from.

**Cut (destructive — one reviewed pass)**
- `resolve_transcript_selection(editId, intent:"remove", selections:[...], revision)` → `payload.tool` + `payload.input` when `readyToApply: true`. Selections: `boundary_range` with `text` anchors (opening quote → closing quote; add `occurrence` if a quote repeats), `span` (a whole row), `word_range`, or `time_range`. Warnings fail closed with `payload: null` — disambiguate, never guess timestamps. **The payload is scoped to the revision you resolved against:** if any cut lands between the resolve and the execute (a `remove_fillers`, a hand edit), every playable range after it has moved — re-resolve, never execute a stale payload.
- `cut_time_ranges(editId, cuts:[{startMs,endMs,source:"user"}], expectedRevision)` → execute the resolver payload **unchanged**. Ordering and source-time conversion are handled server-side. This is the only ungated cut route — always use it for removals.
- `remove_fillers(editId, method:"Cut", expectedRevision)` — transcript-labelled ums/uhs/disfluencies. `"Smart"` (mute <500 ms, cut ≥500 ms) if the Cut result reads choppy on a fast talker. No audio is ever synthesised on this engine.
- `remove_pauses(editId, thresholdMs, expectedRevision)` — 1500 long-form (avoid harsh cuts), 1000 on a reel (cut tighter), 800 on a trailer.
- Undo any of the three: `restore_audio_cleanup(editId, cleanup:"fillers"|"pauses"|"smart_mutes")`.

**Audio & look (non-destructive)**
- `set_magic_audio(editId, trackId, enabled:true, mixLevel, expectedRevision)` — on **every speaker track** (read `trackId`s from the timeline). **0.70** default (an ordinary mic; 0.55 was inaudible on a real edit); **0.85** phone / echoey room; 1.0 only for a bad room; 0.45 or off only for a pro mic in a treated room, with the reason in the log. Read the track back: the `audio.enhancedAudioMix` keyframe carries `enabled:true` and your `mixLevel` (live-read). If the response says the enhanced audio is unavailable/skipped, the recording hasn't finished processing — wait, don't loop.
- `set_color_correction(editId, target:{kind:"track", id}, adjustments:{brightness, contrast, saturation, colorTemperatureKelvin?}, expectedRevision)` — the visible-but-natural values in `${CLAUDE_PLUGIN_ROOT}/shared/footage-look.md` (+0.04 / +0.12 / +0.08 default; never past the over-cooked line).
- `apply_smart_mutes(editId)` — multi-speaker only (mutes the non-speaker's track). Skip on a solo talking head.

**Format & layout**
- `batch` op `update_aspect_ratio {ratio:"9:16"}` — **FIRST, before any overlay exists.** The connector rejects the change once any non-scene overlay has `video.size` keyframes (every B-roll clip, card, banner, and logo has them). That is why reels and trailers are cloned from a **cut-only master** (below), never from a finished edit. Then `apply_smart_layout(editId, style:"FullScreen")` — a solo speaker lands on `solo-fullscreen-1-tile-portrait`. Read the timeline after to confirm the canvas is now portrait.
- Face centring / headroom: `batch` op `update_scene_slot_settings {sceneId, updates:{"<tileId>":{trackId:<trackUniqueId>, positioning:{scale:1.0, offset:{x,y}}}}, overwrite:true}` — the `positioning` wrapper and the `trackId` are required; a bare `{offset, scale}` returns success and writes nothing (live-tested). Offsets are canvas pixels; small only, never crop the head.
- Split-screen (horizontal b-roll on a vertical reel): `batch` op `change_layout {layoutId:"solo-half-vertical-side-1-tile-portrait", sceneIds:[…]}` (speaker in the top half; captions move to middle-centre in that layout — re-pin them for those scenes with `batch` op `update_scene_caption_settings {sceneId, captionsJson:"{\"show\":true,\"position\":{\"x\":0.5,\"y\":0.47},\"style\":{…}}"}`, or keep it simpler and time the b-roll over a cutaway instead).

**Captions**
- `set_captions(editId, show, position:{x,y}, style:{…}, presetId?, studioId?, expectedRevision)` — one call, merged onto current settings. The karaoke recipe is in `${CLAUDE_PLUGIN_ROOT}/shared/caption-style.md`. **Long-form: `set_captions show:false` is a MANDATORY pass, not an omission** — an edit the agent created in Riverside can arrive with captions already ON (live-tested: the Riverside-made edit rendered big boxed uppercase captions on top of the pop-ups until they were switched off). Inside a `batch`, the equivalent ops are `update_global_caption_settings {captionsJson}` (a JSON STRING `{show, position:{x,y}, style:{…}}`) and `set_captions_visibility {show}`.

**Graphics & text (kit first, native second)**
- **Kit banner / strip / panel / icon (preferred when `brand.assets` is populated):** every kit v3 piece is a full-canvas transparent overlay drawn in its zone, so placement is the same for all of them. `insert_overlay(editId, assetId, startMs, durationMs, expectedRevision)` (the media id from `brand.assets.riverside_media_ids`; returns `clipId`; lands at 90% size) → ONE `batch`: `modify_scale {clipId, time:{n:0,d:1}, scaleW:W, scaleH:H, canvasWidth:W, canvasHeight:H}` (true full-frame; `W,H` = `settings.canvas`) + `set_overlay_clip_animations {clipId, inAnimation:{animationType:"slideLeftIn", duration:{n:1,d:2}}, outAnimation:{animationType:"fadeOut", duration:{n:3,d:10}}}` → for the hook banner and the emphasis panel, the words as ONE `insert_text_overlay` with `effect:"shadow"`, `trackZIndex:30`, starting 0.3 s after the panel and ending with it → `modify_position` into the panel's empty zone (the centring rule in `graphics-style.md`). CTA banners have their words baked: place, scale, animate, nothing on top; the primary `cta_*` banner holds from the CTA line's first word to the last frame; the `cta_pack` variant for every other spoken ask (`cta-pack.md`). An icon is the same `insert_overlay` with `position` as canvas fractions, then `modify_scale` to about 36 canvas px on 16:9 (a 100 px badge at 1080p) or 50 on 9:16. **LIVE-TESTED 2026-09-21** on a real edit (hook panel, name strip, emphasis panel, icon, words centred, exported).
- **Native card (the fallback when no kit is registered):** `batch` op `insert_text_overlay {desiredInsertionTime:{n,d}, duration:{n,d}, name, trackZIndex:10, text, role:"TITLE", fontFamily, fontSize, color:"#FFFFFF", effect:"boxed", animation:[{name:"popIn",type:"in",duration:0.3,offset:0},{name:"popOut",type:"out",duration:0.25,offset:0}]}` → the op's result carries the new clip's id (`data.clipId`, LIVE-TESTED) → `batch` op `modify_position {clipId, time:{n:0,d:1}, positionX, positionY, canvasWidth, canvasHeight}` to the format zone (`graphics-style.md`). One card = ONE text object. The `boxed` effect is the panel — its colour is Riverside's default (dark on white text); **you cannot brand the panel colour natively** — which is exactly why the kit is preferred. `modify_text_properties` needs EVERY field (`text, color, font, fontSize, textAlign, textTransform, textEffect, anchor`) with `null` for the ones to keep.
- `add_text_overlay(editId, text, role:"title"|"subtitle"|"body"|"speaker", startMs, durationMs, style:{color, effect, fontFamily, fontSize})` — the same built-in presets without positioning; fine for a centred title over B-roll, not for an off-face card on a talking head.
- **Name strip:** the kit's `lower_third` overlay (above) for ~5 s on first appearance; if no kit, `add_lower_third(editId, name, title, startMs, durationMs)` — built-in speaker style (Inter 64, shadow, two centred lines). **LIVE-TESTED: it inserts DEAD CENTRE on the face, not lower-left.** Always follow it with `batch` `modify_position {clipId:<returned clipId>, time:{n:0,d:1}, positionX:200, positionY:305, canvasWidth:640, canvasHeight:360}`. Long-form only.
- **Logo:** `batch` op `insert_logo {assetId, placement:"topRight", opacity:0.7, width:{n:1,d:8}}`; it FAILS if a logo already exists (a Riverside-made edit, or one that ran `apply_brand`) — then `replace_logo {assetId}`, or `change_logo_layout` / `change_logo_opacity` to adjust. `apply_brand(editId, studioId)` applies the studio kit's logo, design, CAPTIONS PRESET and intro/outro in one go — never use it inside a pass (it can switch captions back on over a long-form and add an intro/outro you did not plan); it is a setup-time option only.

**Energy — zooms are SCENES, never keyframes (LIVE-TESTED 2026-09-21, the only form that works)**
- One zoom = (1) `batch` two `split_scene_at_time {splitTime:{n,d}}` ops at the SOURCE-time start and end of the key line — the word-level `assetStart` of its first word, and of the first word after it (one split only when the line runs to the end of the video); (2) `read_timeline_in_range` inside that window → the new scene's `uniqueId`, its tile id (the key under `slotSettings`, `fullscreen` on a solo layout) and the `trackUniqueId` in it; (3) `batch` `update_scene_slot_settings {sceneId, updates:{"<tileId>":{trackId:<trackUniqueId>, positioning:{scale:<1.06|1.10|1.14>, offset:{x:0,y:0}}}}, overwrite:true}`. It is a HARD-CUT zoom (the jump-zoom every talking-head channel uses), so it starts and ends on a phrase boundary and holds for the whole line (about 2.5–6 s). Sizes, rate, and the three moves (zoom in, step-back, jump-cut cover) are in `${CLAUDE_PLUGIN_ROOT}/shared/effects-menu.md`.
- **Batching:** do ALL the splits for the video in one or two batches (≤100 ops each), read the timeline once, then ALL the slot settings in one batch. Three batches for a 10-minute video, not thirty.
- **Time axes:** emotion events and compact rows are PLAYABLE; the split needs SOURCE. Take each beat's first word from `read_aligned_transcript(detail:"words")` and use its `assetStart` directly. The swoosh (`insert_audio`) takes PLAYABLE ms — use the word's `playableStartMs`, not the split time.
- Read every zoomed scene back and confirm `positioning.scale` is there, then verify one frame per size used (no edge, comfortable headroom). **What does NOT work (all return `success` and write nothing):** `modify_scale` on the recording track or clip at any time, `set_visual_crop` on a split recording clip, a duplicated recording clip scaled on its own track, and `updates:{tile:{trackId, scale}}` without the `positioning` wrapper. Never report a zoom you have not read back.
- Swoosh: `insert_audio(editId, assetId:<config.sfx.swoosh_media_id>, startMs:<playable ms>, dB:-10)` — only if that id exists. Riverside's library has no sound effects.

**B-roll & music**
- Stock: `get_stock_media(query, mediaType:"video"|"image", count)` → `insert_stock_media(editId, externalSourceId, mediaType, startMs, durationMs, position)` (imports + places server-side; `startMs` is SOURCE time). Query with daytime words and never place a clip darker than the speaker's shot (`broll-ladder.md`). **LIVE-TESTED:** every overlay lands as a CLIP on the single "Default Overlay Track" at **90% of the canvas with a 5% border** (`video.size` 0.9×0.9). Full-cover it with ONE batch after all inserts: `modify_scale {clipId:<overlay clip uniqueId>, time:{n:0,d:1}, scaleW, scaleH, canvasWidth:640, canvasHeight:360}` — the timeline's reference canvas is **640×360** regardless of export resolution; use aspect-correct cover sizes (16:9 clip → 640×360; a 1.9:1 clip → 683×360; a 2.37:1 clip → 854×360). Verified on frames: edge-to-edge, no bars. Entrance: none (a hard cut) on the bold packs; `set_overlay_clip_animations … inAnimation:{animationType:"fadeIn", duration:{n:3,d:20}}` on the calm packs.
- Own footage: `media_create_media_upload(fileName, mimeType, fileSizeBytes, productionId, studioId)` → `curl -T <file> -H "Content-Type: <mime>" "<uploadUrl>"` → `media_finalize_media_upload(mediaId, thumbnailUploadUrl for video)` → poll `media_get_media(mediaId)` until `transcoded`/`done` → `insert_overlay(editId, assetId, startMs, durationMs)` → full-cover scale as above. ≤500 MB per file. This works where a shell and the local file exist (the Code tab); **in Cowork, or whenever the push fails, do not loop:** ask the agent to drop the clip into Riverside's Your Media panel, then find it with `media_list_media(productionId, search)` by name.
- Music bed: `get_stock_music(collection, section:"underscore", count)` → `insert_audio(editId, assetId:<mediaId>, startMs:0, dB:-18 (reel) | -22 (long-form), fadeInMs:800, fadeOutMs:1500)`. Free library, licensed. Mood table in `${CLAUDE_PLUGIN_ROOT}/shared/music.md`. If the bed is shorter than the video, insert it again at its end (or pick the Long variant). **Section stingers (long-form):** `get_stock_music(collection:<same as the bed>, section:"transition")` → `insert_audio(assetId, startMs:<section start, playable>, durationMs:1800, dB:-12, fadeOutMs:600)` — a 1.8-second slice of a transition track at each section change (`music.md`; the slice inserts, live-tested 2026-09-23).

**Chapters, export, publish**
- `batch` ops `add_chapter {time:{n,d}, title}` and `move_chapter {chapterId, newTime}` — native chapter MARKERS, for the agent's navigation in the editor. The connector can add and move markers, never rename or delete them. **The Studio never names a chapter** (`${CLAUDE_PLUGIN_ROOT}/shared/boundaries.md`): marker text is the section's first spoken words in quotes, the section map (playable `00:00` times + a plain note) goes to the YouTube System, and the chapter NAMES the viewer sees live in the SEO Package's description. A Riverside-made edit already carries 3–4 AI-generated markers (live-tested): move them onto the section starts rather than adding beside them. This is the Section Map pass (`sections.md`), run once the cut is locked.
- `exports_create_export(sourceEditId, composeSettings:{export:{quality:"1080p", fileName:"<slug>"}}, creationSource:"web")` → returns the export `id` immediately → poll `exports_get_export(id)` every ~30–60 s until `COMPLETED` (minutes for a long video; `FAILED` is terminal → report, don't re-fire blindly). **Always `1080p`** — on a 9:16 edit that renders 1080×1920. 4K only if the source is 4K AND the agent asks. The result is an **S3 key, not a link** — the agent gets the file from Riverside's Exports, and that file is what you frame-QA if reachable (`${CLAUDE_PLUGIN_ROOT}/shared/frame-qa.md`).
- Publishing: `${CLAUDE_PLUGIN_ROOT}/shared/publishing.md` (gated).

## Time axes — the one conversion you must get right (live-tested twice)

**The clean way (run 2):** `read_aligned_transcript(detail:"words", startMs, endMs)` returns `assetStart`/`assetEnd` per word — those ARE source times. Place cards, cutaways, name strips, scene splits, and markers at `assetStart.n / assetStart.d` seconds of the word they belong to. No offset arithmetic, no drift. Read the words in windows around the moments you picked from the compact rows.

**The fallback:** the compact rows and the emotion events speak **playable** ms (post-cut). The placement tools (`insert_stock_media`, `insert_overlay`, `add_text_overlay`, `add_lower_third`, batch `insert_text_overlay`, `add_chapter`, `split_scene_at_time`, keyframe `time`) speak **source** time. After any cut, convert: `source = playable + (total duration of synced cuts whose source start < that point)` — read `syncedCuts[]` from the timeline once and build the offset table (11 filler cuts on a 12-min video added up to 4.6 s by the end, i.e. a card placed by playable time would drift ~4 s late by the CTA). `cut_time_ranges`, `insert_audio`, and `insert_media_as_scene` are the exceptions: they take playable ms and convert for you.

## Getting the video IN — read this first (it's where edits fail)

There is **no import-by-URL** on this connector. The main recording gets into Riverside one of three ways, and you only ever *find* it:

1. **Recorded in Riverside** (the natural fit — Riverside is a recorder first). `platform_list_recordings` → it's there.
2. **Uploaded in the Riverside dashboard** — the agent drags the file into their project (Riverside handles multi-GB 4K uploads in the browser). Until `status` stops saying `uploading`/processing, the transcript and Magic Audio don't exist yet → **wait; say so in one line; don't create the edit early.**
3. **Not in Riverside at all** → *"Upload it to your Riverside project first — drag it onto the project page — and tell me when it's done."* Never try to push a big local file through the media upload (500 MB cap, and it lands in Your Media, not as a recording).

Then: `platform_get_recording` → `project.id` + `studioId` → `create_edit_from_recording` → `read_aligned_transcript`. If the transcript read returns `FAILED_PRECONDITION` with `transcript_load_failed`, it's still processing — wait a few minutes and try once more; `no_session_ids` means the edit has no recording behind it — wrong edit, pick again.

## The cut-only master (why reels never come from a finished edit)

A finished long-form carries B-roll, banners, a name strip, and a logo, and every one of them has `video.size` keyframes — so `update_aspect_ratio 9:16` on a clone of it is REJECTED by the connector. The fix is one extra clone at the right moment:

- In the long-form line, the moment the cut is locked (hook + fluff done, before the section map, audio, and any overlay): `clone_edit(sourceEditId, title:"<title> — master (cut only)")`. Log its id: `master · <editId>`.
- Every reel (`repurpose.md`), the trailer (`trailer.md`), and the 16:9 copy of the trailer are cloned FROM THE MASTER, never from the finished long-form. A standalone reel from a fresh recording needs no master (nothing is overlaid yet).
- The master is never edited itself. The finished long-form continues on the original edit.

## General habits (always)

- **Work on ONE edit** (plus the snapshot and the master when the line calls for them). Never create a second edit "to try something" — the agent ends up with mystery duplicates in their project.
- **Clean starts & ends — OPEN ON THE HOOK.** Resolve a cut from `0` to the first word of the confirmed hook line; trim the camera-off reach / dead air at the end — but NEVER cut into the hook or the CTA. End on a complete thought.
- **Magic Audio — its own step, on every speaker track, at an audible level, confirmed.** Read the timeline after: the track shows an `audio.enhancedAudioMix` keyframe with `enabled:true` and the level. If it silently didn't apply (recording still processing), say so — don't ship "cleaned audio" that isn't.
- **Verify each pass with a diff**, not a vibe: `compare_revisions(fromRevision, toRevision)`. Log the pass.
- **NEVER enable background removal / blur / eye correction on a talking head.** `modify_background` and `modify_eye_correction` exist in the batch surface — they are banned here (`${CLAUDE_PLUGIN_ROOT}/shared/cost-discipline.md`).
- **Overlay keyframes live at time 0 only.** Size and position right after the insert: fine. Anything later on an overlay clip hangs the editor (live-tested) — use `set_overlay_clip_animations` for motion.
- **Publishing is gated** — never `social_upload_create` without the summary + explicit yes.
- **A timeout is not a failure** — `get_revision` first; if it advanced, diff it.
- **`CONFLICT` = the agent is probably in the editor right now.** Follow the one rule in `${CLAUDE_PLUGIN_ROOT}/shared/house-rules.md`.

## THE PASS PLANS — fewest passes (the speed + correctness lever)

**Start with the free pre-flight** (`${CLAUDE_PLUGIN_ROOT}/shared/preflight-check.md`) — read the transcript with the emotion events, find the duplicate takes, quote the plan + time, get one yes. Then the passes. Each pass = a small group of writes with ONE diff to verify and ONE checkpoint line.

**SHORT-FORM reel — 4 passes:**
1. **CLEAN** — `update_aspect_ratio 9:16` (batch) → `apply_smart_layout FullScreen` → the reviewed cuts (`cut_time_ranges` from the resolver: open-on-hook, duplicate/bad takes, tail) → `remove_fillers Cut` → `remove_pauses 1000` → `set_magic_audio 0.70` (0.85 phone) on the speaker track(s). Preview the cuts (from the free transcript read) and get a yes BEFORE firing; verify with `compare_revisions` + a fresh `read_aligned_transcript` (does it open on the hook? does it end on the last word?).
2. **CAPTIONS** — `set_captions` karaoke (brand style, `fontSize 84`, y≈0.84, `widthRatio 0.8`). Spelling check: read the aligned transcript for the agent's name / brokerage / city — if wrong, they fix it in the Riverside transcript panel first (free, a minute), then re-read.
3. **B-ROLL** — ≤3: `insert_stock_media` / `insert_overlay` on the exact words, each full-cover scaled, bright, never over hook/face/CTA.
4. **FINISH** — `set_color_correction` visible-but-natural → 3–4 zooms on the beats (one per 12–20 s; 1.06 / 1.10 / 1.14 by strength) plus a size change on each editorial cut (+ swoosh if the agent has one) → music bed at -18 dB (`insert_audio` maps the bed onto SOURCE time across the cuts; a 37 s library track covers 37 s of PLAYABLE reel — insert it again at `startMs:<track length>` to cover the rest) → hook banner (first ~2 s, top zone; native card `fontSize 72`, ≤20 chars if no kit) → the `cta_pack` variant on any mid-reel ask → the primary CTA banner from the CTA line's first word to the last frame (top zone) → the logo with `insert_logo` / `replace_logo` if the kit has one. Diff, log, then the measured gates (`final-check.md`, timeline reads), **ONE export at 1080p**, frame-QA, deliver. **Live-tested reel recipe (46 s from a 70 s raw intro): 18 revisions, ~12 min, zero credits.**

**LONG-FORM — ≤7 passes:** ① open-on-hook + filler words (`cut_time_ranges` for the pre-hook + `remove_fillers Cut`; verify the first 40 s) · ② dead air + duplicate/bad takes + the blooper second pass (`remove_pauses 1500` + the resolved cuts — the reviewed destructive pass; snapshot first if the recording exists nowhere else) → **clone the cut-only master** → the section map + markers (`sections.md`) · ③ Magic Audio 0.70 + the visible grade + **captions OFF** (three non-destructive calls) · ④ B-roll (~1 per 45–60 s, bright, all placed in one go, each full-cover) · ⑤ energy (zooms at one per 45–75 s sized to the beat, a step-back on the reveal, a size change on every editorial cut, + swoosh if the agent has one) · ⑥ music (the bed at -22 dB across the final length + a 1.8 s stinger at each section change) · ⑦ graphics (hook banner → name strip once the banner has cleared → an emphasis pop-up every ~2–3 min → the `cta_pack` variant on each spoken ask → the primary CTA banner from the CTA line to the end → the logo). The section map and frame-QA are FREE Claude work; titles, descriptions, chapter names, and tags belong to the YouTube System. **Budget one "text fix" round** — sizing usually needs a correction after the first frame-QA; that's normal.

**LISTING reel — ≈4 passes** (the short-form plan; address/price cards join FINISH; the room cutaways are the B-roll pass). A long YouTube tour follows the long-form plan.

**QUALITY CHECK, THEN ONE RENDER:** every blocker that can be measured from the timeline (audio level, grade band, music present, zooms at the rate, bloopers gone, caps) is checked BEFORE the export, so a miss costs a write, not a render. `exports_create_export` once at `1080p` on approval; the visual blockers are read on that export or the editor preview. Re-export only if a visual blocker fails.

## Concurrency & the revision rule

There is no documented per-session query limit. The thing that WILL bite is **optimistic locking**: every write should carry `expectedRevision` from your last read; if the agent nudges anything in the editor between your read and your write, the write returns `CONFLICT` and nothing is saved. Rules:
- Read → write → read the returned revision → next write. Don't reuse a stale revision across a pass.
- On `CONFLICT`: follow the one rule in `${CLAUDE_PLUGIN_ROOT}/shared/house-rules.md` — a harmless editor-tab re-save gets one retry; a real hand edit means stop and ask.
- Batches are atomic: on `failedOperationIndex`, nothing in that batch landed — fix that one op, re-send the whole batch.

```
<pass name> · done · rev <revision>
```

(e.g. `clean · done · rev 7` / `captions · done · rev 8` / `broll · done · rev 12`, plus `master · <editId>` once the cut-only master exists). Write the line only AFTER the diff confirms it. The log lives in the Brain and travels with it: pull before reading, push after writing (`house-rules.md`, the persistence rule) — in Cowork the local copy is gone at the end of the session.

**At the START of any long-form or listing edit, check for this log first.** Log exists → one plain line, run only the unlogged passes. Log missing → `compare_revisions("1", head)` tells you the truth (toggles + cuts + scenes) — state it, one-word confirm, continue.

### Named failure modes (say the plain words, don't retry)

- **Still processing** (`FAILED_PRECONDITION` · `transcript_load_failed`, or Magic Audio "skipped"): *"Riverside's still finishing your upload — give it a few minutes and say 'go' and I'll start."*
- **Feature gated** (`FAILED_PRECONDITION` on `create_edit_from_recording` / `set_brand`): use the fallback in the tool list above; say what you did in one line.
- **Conflict**: *"Looks like you're in the editor at the same time — I've paused so nothing gets overwritten. Say 'go' and I'll pick up from where it is now."*
- **Export failed** (`FAILED`): report it; check `get_revision` still matches; re-fire ONCE only if the agent says so.
- **Aspect-ratio change rejected**: an overlay exists on this edit. Clone from the cut-only master instead; never delete a finished edit's overlays to force it.

## Playbook A — long-form (≤7 passes)

1. Find the recording (`platform_list_recordings` → not `uploading`) → `platform_get_recording` → `create_edit_from_recording(sessionId, projectId, title:"<Video title> — edit")` (or the gated fallback). `read_aligned_transcript(editId, includeParalinguistics:true)` → revision R0.
2. **FREE PREP:** read the compact rows and the emotion events; **IDENTIFY the hook line** (confirm it so the open-on-hook cut can't clip real content); find **duplicate takes** (same point twice — keeper is usually the later, complete one; quote the distinguishing line of each) and Riverside's own AI retake flags (`comments[]`, `clean-cut.md`); note **section changes**, the **featured moments** (the biggest emotion events + numbers + reveals: they get the biggest zooms and the pop-ups), and where the B-roll goes; read `identity/compliance.md`; build the **spelling list** (name / brokerage / city) and check the transcript for it. Quote the plan + time; get the yes.
3. **PASS ① — open on the hook + filler words:** resolve `time_range 0 → hook first-word` (or `boundary_range` from the first spoken word to the word before the hook) with intent `remove` → `cut_time_ranges` → `remove_fillers Cut`. Re-read the first 40 s of the aligned transcript. Log.
4. **PASS ② — dead air + duplicate/bad takes (the reviewed destructive pass):** `remove_pauses 1500` → resolve each duplicate take, false start, and restart phrase as a `boundary_range` (opening quote → closing quote, `occurrence` where needed) → one `cut_time_ranges` with all of them. **The agent saw this list in the pre-flight — that was the hard gate.** Diff: `durationBeforeMs → durationAfterMs` should match the quoted cut. Re-read the whole transcript once: no sentence twice, no restart phrase left. Log. **Then `clone_edit` the cut-only master** (`master · <editId>`), and run the Section Map (`sections.md`: the `00:00` map for the YouTube System, markers moved/added by first spoken words). Log.
5. **PASS ③ — Magic Audio + grade + captions off:** `set_magic_audio` every speaker track at 0.70 (0.85 phone/echo) → `set_color_correction` on the speaker track (+0.04 / +0.12 / +0.08, or the pack's values) → `set_captions show:false`. Read back the track; confirm the audio keyframe (`enabled:true`, the level) and the `colorCorrection` values exist. Log.
6. **PASS ④ — B-roll:** `studio-broll` picks every moment from the transcript first (free), then places them all: ~1 per 45–60 s, each 2.5–5 s, full-cover, bright, unique, instantly recognisable, never over hook/face/CTA; a midpoint frame check on each cutaway for brightness. Verify the count on the timeline. Log.
7. **PASS ⑤ — energy:** the emotion-driven plan (`effects-menu.md`): zooms on the beats at one per 45–75 s (1.06 / 1.10 / 1.14 by strength), a step-back on the biggest reveal, a size change on every editorial cut, + swoosh if the agent has one. All the scene splits in one or two batches, one timeline read, all the slot settings in one batch. Read the scenes back; one frame per size. Log the count and the sizes.
8. **PASS ⑥ — music:** `get_stock_music(collection, section:"underscore")` Low → `insert_audio` at -22 dB across the final length (again at the track's end if it is shorter) → one 1.8 s `transition` slice at each section change (`music.md`). Off only if the agent said so or the topic is serious — logged. Log.
9. **PASS ⑦ — graphics:** hook banner (first ~2 s, with the hook line typed into its zone) → the name strip for ~5 s, starting at least half a second AFTER the hook banner clears (they share the lower-third zone; never both at once) → an emphasis pop-up every ~2–3 min with its phrase typed in → the `cta_pack` variant on each spoken ask (`cta-pack.md` table) → the primary CTA banner from the CTA line's first word to the last frame → the logo (`insert_logo`, or `replace_logo` if one exists). **16:9 → everything in the LOWER THIRD**, sized per `graphics-style.md`. Compliance-check every typed word first. Diff; log.
10. **CHECK, RENDER, DELIVER (free):** the measured gates from the timeline (`final-check.md` blockers 1–8) → **ONE export at 1080p** on approval → frame-QA on it (`frame-qa.md`) for the visual gates → fix + re-export only if a visual blocker fails → hand over as a review draft with the section map (never titles, descriptions, or chapter names; `boundaries.md`) → offer reels, the trailer, and to publish.

## Playbook B — short-form / pull shorts

Two modes: **standalone reel** (steps 4–5 below) and the **repurpose batch** (one long video → N clips).

### B0 — Repurpose batch (long → N clips)

1. **Scope & confirm N** (default 3, cap 5). One number, one yes.
2. **The source is the cut-only master.** If the long-form line ran, its log names the master (`master · <editId>`). If not (a long recording that was never edited), create ONE edit, run the reviewed clean cut on it, and clone the master from that. Read the master's aligned transcript once (revision R0). The master itself is never cut.
3. **SCORE candidate spans (free):** every contiguous 20–60 s span, 0–2 on five criteria — self-contained · hook line · high-value/emotional (use the emotion events) · clean payoff · length-fit (30–45 s ideal). Keep ≤10.
4. **PICK the top N distinct** — no overlaps, no same-topic repeats. Can't find N strong ones → say so.
5. **Per clip = its own edit.** `clone_edit(masterEditId, title:"Clip N — <hook line>")` → on the clone, `resolve_transcript_selection` the head (0 → clip first word) and the tail (clip last word → end) with intent `remove` → ONE `cut_time_ranges` with both. Then run the standalone 4-pass recipe on that clone (9:16 first — it works because the master has no overlays). **Sequential, each to done**, checkpoint line per clip (`clip-1 <hook> · done · rev n · <editId>` in the SOURCE edit's log).
6. **Frame-QA each clip**, then **deliver all N at once**, labelled by hook line. Export each at 1080p on approval.

### Standalone reel — 4 passes (also the per-clip recipe in B0)

1. Find/create the edit (a fresh `create_edit_from_recording`, or the clip clone from B0); read the aligned transcript with the emotion events (R0). **If the recording is 16:9 (it usually is), the reel becomes 9:16 in pass 1 — do the aspect change FIRST, before anything is overlaid.**
2. **FREE PREP:** the brief (`creative-direction.md`, five lines), the moment (hook → idea → payoff/CTA), the hook line, the spelling check, compliance.
3. **PASS 1 — CLEAN:** `update_aspect_ratio 9:16` → `apply_smart_layout FullScreen` → the reviewed cuts (`cut_time_ranges`: open on the hook, zero dead air via `remove_pauses 1000`, clean end; never cut the hook or the CTA) → `remove_fillers Cut` → `set_magic_audio 0.70` (0.85 phone). Yes before firing; diff after.
4. **PASS 2 — CAPTIONS:** `set_captions` karaoke — brand font/accent, `fontSize 84` (76 clean-minimal, 80 cinematic), `position.y ≈ 0.84`, `widthRatio 0.8` (keeps text out of the right ~12% icon rail), `textAlign Center`.
5. **PASS 3 — B-ROLL:** ≤3, full-cover, bright, on the words, never repeated, never over hook/face/CTA. Horizontal clip that dies when cropped → split-screen layout (`layouts.md`).
6. **PASS 4 — FINISH:** grade (+0.04 / +0.12 / +0.08) → 3–4 zooms on the beats (one per 12–20 s, sized to the beat) + a size change on each editorial cut → music bed -18 dB → hook banner (top zone, ~2 s) → the `cta_pack` variant on any mid-reel ask → the primary CTA banner from the CTA line to the end (top zone) → the logo with `insert_logo` / `replace_logo` if the kit has one. Diff; log.
7. The measured gates → **ONE export at 1080p** on approval → frame-QA → fix + re-export only on a visual blocker → review draft → offer to publish (`studio-publish`).
